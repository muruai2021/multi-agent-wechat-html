# 公众号文章写作原则（老石版）

> 本文件记录老石公众号文章的写作偏好和非官方约束，适用于所有内容创作场景。

---

## 核心原则

### 1. 原创分析 > 素材复述

**最高优先级原则**：文章里70%以上应该是你自己的话和观点。

当用户提供素材（播客笔记、干货内容、访谈记录）并说"深化"或类似表述时：
- **不要**：按素材的原始叙事顺序分点，逐一描述"素材A说了X，素材B说了Y"
- **要**：找到素材中的核心论点，用自己的逻辑框架重新组织，提出独特分析和见解

**判断标准**：如果把原文素材全部删掉，文章还能独立成立吗？如果能，这篇文章有灵魂。如果不能，说明你在复述而不是创作。

---

### 2. 不引用"说了什么"，只引用"意味着什么"

素材中的引文（金句、观点）不应该直接引用原文，而是：
- 引用后立刻给出你自己的解读
- 或者根本不用原文，而是用你自己的话重新表述这个观点

**示例**：
- ❌ "某某说：'Markdown是给人类想象用的，不是给机器执行的'。"
- ✅ "这揭示了一个根本矛盾：Markdown的'人类可读性'恰恰是它在AI时代的缺陷。"

---

### 3. 结构服务于逻辑，不服务于素材

文章结构应该由核心论点决定，而不是由素材的原始顺序决定。

好的文章结构示例：
```
观点A：Markdown的本质是视觉暗示（你的分析）
    → 但AI需要的是结构语义（你的推论）
观点B：HTML的DOM树是机器可操作的有序图（你的分析）
    → 这解决了什么问题（你的应用）
观点C：可预览性让人类回到协作核心（你的分析）
    → 进一步推演（你的洞察）
```

---

### 4. 章节顺序按说服力排列，不按素材顺序

当有多个论点时，优先顺序：
1. **感性认识先**（人类能直观理解的现象）→ 例：先讲"可预览"因为这是人能直接感受到的
2. **理性分析后**（技术原理、结构问题）→ 例：再讲Markdown的语义缺陷
3. **结论收尾**（升华、行动指引）

---

## 禁止事项

- ❌ 直接复述播客/素材内容超过30%
- ❌ 按素材的原始时间线/叙事顺序安排章节
- ❌ 在文章里频繁使用"素材说"、"嘉宾指出"、"节目中提到"
- ❌ 用引用块堆砌代替自己的分析

## 鼓励事项

- ✅ 用具体的技术细节（HTML标签、CSS变量）支撑抽象论点
- ✅ 用表格/对比来组织信息（比文字列表更直观）
- ✅ 金句块只放**你自己的洞察**，不放引文
- ✅ 在结尾给出超越素材的延伸思考

## 本次教训（2026-05-22）

**触发事件**：用户提供播客笔记，要求"深化HTML替代Markdown"主题。初始版本按播客叙事顺序分7个论点，大量引用"Thariq说"、"Clara说"，变成了播客内容复述而非独立文章。

**正确做法**：找到素材中的核心逻辑线（Markdown给人类"想象"用，HTML给机器"执行"用），用自己的分析框架重组，用自己的案例和表述方式重写。

**教训**：用户说"深化" = "给我你的分析，不要素材的复述"。这是一个必须立即识别的信号。

## 本次教训（2026-06-17 · 商业级严谨专项）

**触发事件**：写《Agent Skills 上岗证》公众号文章，从 V1 传播型 → V6 商业级严谨，连续 6 轮用户反馈。核心问题：**把"产品设计稿"包装成"已存在产品"** + **所有"未验证具体数字"硬塞进文章**。

### 4 条硬约束（v3.0 新增 · 必查）

#### A. 凭空捏造产品表述（绝对禁止 · 一票否决）

- ❌ 编造不存在的工具名称
- ❌ 编造不存在的 URL（例：`https://muru.ai/agent-skills-radar` 是凭空编的）
- ❌ 描述不存在的功能（H5 / 5 项成果物 / 个性化计划等凭空编）
- ❌ 编造不存在的运营动作（朋友圈话题"同步上线"等）
- ❌ 编造产品文件名后缀（`Skill.md` / `Workflow.json` / `Portfolio` 等）

**判定原则**：文章中所有"产品相关"内容（URL / 功能 / 流程 / 营销动作）必须真实存在；如果是设计稿，要么明确标注"待开发 / 即将上线"，要么删掉；不能包装成"已存在产品"。

#### B. 数据限定语模板（必加 · 5 种）

| 类型 | 模板 | 用途 |
|------|------|------|
| 官方数据 | "据…财报 / 据…官方 / 据…公告" | 来自一手可信来源 |
| 媒体转述 | "据…报道（注：该数据为媒体转述）" | 二手数据 |
| 公开估算 | "据公开市场估算" | 公开但非官方数字 |
| 经验估算 | "按经验估算""通常：…" | 经验数字 |
| 综合观察 | "综合多份样本观察" | 行业观察 |

**判定原则**：每条数据必须能套上至少一种限定语；套不上 = 不允许出现。

#### C. 时间逻辑要精确（必查 · 3 处易错点）

- ❌ 把不同口径数据说成"同一份报告"（例："74% + 60% 是不同来源、不同口径"）
- ❌ 用模糊时间代替具体月份（"春节后"应改为"2025 年 2 月"）
- ❌ 擅自加原文没有的限定（原文"高达 50%"不要改成"中位数约 50%"）

**判定原则**：每个数据的时间维度（全年/月/日）必须精确到月；报告发布年份必须标；不同来源的数据必须分别说明。

#### D. 公式 / 模型必须标注"非实证"（必加 · 2 类）

- **经验公式**：加"这是按经验总结的思考框架，**不是经过实证的公式**"
- **经验分布**：加"具体分数是经验观察的**示意性分布**，不是来自某具体研究"

**判定原则**：所有非实证的公式、模型、分布、等级表，必须加"经验"或"非实证"标注；读者不能把"思考框架"误读为"科学结论"。

### 全文 4 维体检框架（v3.0 新增 · 交付前必过）

每篇文章交付前必须过一遍：

| 维度 | 检查项 | 通过标准 |
|------|--------|----------|
| 案例真实性 | 每个数据/案例可追溯 | 0 个未标注来源的数据 |
| 案例-论点相关性 | 每段是否扣题 | 0 个"为存在而存在"的案例 |
| 整体逻辑 | 章节顺序是否闭环 | 趋势→定义→模型→自评→案例→组合→路径→行动 |
| 可读性 | 段落长度 + 人味细节 | 每段 ≤ 200 字 + ≥ 3 个具象场景 |

### V1→V6 升级路径（参考）

| 版本 | 状态 | 关键动作 |
|------|------|----------|
| V1 | 传播型 | 写手出初稿 + verify 12 项 |
| V2 | 概念闭环 | 5 层架构 + 公式 + 6 维按 4 类归类 + 5 等级 + 3 成果物 |
| V3 | 数据稳健 | 全数据加"据…""通常""按经验估算" |
| V3.1 | 时间逻辑 | 74%/60% 分开标注 + 还原"高达 50%" |
| V4 | 删捏造 | 删 H5 / 二维码 / 5 项成果物 / 朋友圈话题 |
| V5 | 删产品化 | 删 Skill.md / Workflow.json / Portfolio / 可下载 / 可售卖 |
| V6 | 体检 | 公式加"非实证" + 雷达图加"示意性" + 加 2 处人味 |

**经验**：V1-V3 是一次写稿的 3 个层级（基础 / 概念 / 严谨），V4-V6 是"先写完再体检"模式。**推荐：先严格按 V4 写（避免捏造），再用 V6 4 维体检收尾**。

## "去 AI 味"清单

写手在初稿和润色阶段必须主动检查并清除以下"AI 风"特征。出现一次扣 2 分（评审维度"人味与去 AI 味"会查重）。

### 禁用第一人称（v1.1 强约束）

**人设**：通俗技术文档口吻，类似阮一峰 / 酷壳（CoolShell） / 美团技术博客的笔法。

**禁用第一人称代词**：
- ❌ 我 / 我的 / 我们 / 笔者的
- ❌ 笔者 / 笔者认为 / 笔者觉得

**替代方案**（按优先级）：
1. **无主语陈述**（最自然）——"凌晨 2 点的 bug session，盯着 600 行 markdown 突然意识到"
2. **用"你"建立读者代入** ——"你写了 5 个 skill，会撞上一堵墙"
3. **用"常见的 / 实际的 / 实际项目中"** ——"实际项目中，4 次是更稳的判断阈值"
4. **用"踩过坑的常见节奏是"** ——"踩过坑的常见节奏是：第 1 周硬塞 12 步崩 5 次回滚"

**人称对照表**：

| 原文（第一人称）| 改后（技术文档人称）|
|------|------|
| 我立刻把自己 30 多个 prompt 改成了 skill | 常见的做法是把 30 多个常用 prompt 改写成 skill |
| 但跑了几千次之后，我撞上了一堵墙 | 但跑了几千次之后，会撞上一堵墙 |
| 凌晨 2 点改 bug，我盯着那 600 行 markdown | 凌晨 2 点的 bug session，盯着那 600 行 markdown |
| 我尝试把这些逻辑塞进 SKILL.md | 常见的尝试是把这些逻辑塞进 SKILL.md |
| 我自己的判断阈值是 4 次 | 实际项目中，4 次是更稳的判断阈值 |
| 我自己踩过坑 | 踩过坑的常见节奏是 |
| 别学我，第 1 步就 3 步走起 | 第 1 步就 3 步走起 |

**评审检查**：写手初稿 Ctrl+F 扫 "我" / "我们" / "笔者" → 命中 > 0 直接打回。

### 禁用套话（出现即扣分）

- 在这个时代 / 当下时代 / 当今社会
- 值得注意的是 / 需要注意的是 / 不难发现
- 综上所述 / 总而言之 / 由此可见
- 我们不禁要问 / 让我们一起 / 让我们共同
- 不是 X，而是 Y（无信息量的对仗陷阱）
- X 是 Y 的本质（空洞定义）
- 提供了无限可能 / 开启了新篇章
- 你 get 到了吗 / 懂了吗 / 学到了吗
- 未来已来 / 未来可期

### 禁用模板句

- 过度排比（连续 3+ 句同结构）→ 1-2 处点睛即可
- 伪结论（"总之，XXX 是一个系统工程"）→ 给出具体行动或观察
- "X 是 Y 的 Z"（"创新是企业发展的核心动力" 这类无信息量句）
- 大段抽象抒情（"人类文明的进程，是..."）

### 禁用"AI 友好"结构

- 3 段式套话开头（"首先...其次...最后..."在没有逻辑递进时不要用）
- 过度对称的"双向论述"（"一方面...另一方面..." 强行制造对立）
- 章节末尾空洞升华（"这是 X 的本质"）
- 全文以"未来展望"收尾的俗套

## "人味"细节技法

写手必须主动在文章中植入至少 **3 个**"人味细节"（评审会统计）。以下技法按优先级排列：

### 1. 具体数字 > 模糊量

- ❌ "很多用户遇到了问题" / "大量的数据" / "不少案例"
- ✅ "凌晨 3 点 21 分" / "22 项检查" / "5 个项目之间精神分裂" / "100% 合规率"

### 2. 具体时间 > 时间感

- ❌ "不久前" / "最近" / "过去" / "未来"
- ✅ "2024 年初" / "周二上午" / "Karpathy 写下那行字的时候" / "踩了两次"

### 3. 具体场景 > 抽象环境

- ❌ "在工作中" / "在生活中" / "日常使用" / "实际场景"
- ✅ "在星巴克写" / "手机弹出提示" / "拉了 5 个项目对比" / "凌晨 3 点死锁"

### 4. 第一人称体验 > 客观陈述

- ❌ "应当注意..." / "很多用户反映..." / "据观察..."
- ✅ "我第一次没写，第二天就被误改了文件" / "我踩过两次" / "试过的都说香"

### 5. 感官细节 > 抽象描述

- ❌ "复杂的" / "庞大的" / "精致的" / "惊艳的"
- ✅ "黏糊糊的" / "嗡嗡响" / "绿底白字" / "代码飘红"

### 6. 个人情绪 > 中立分析

- ❌ "这是一个值得思考的问题" / "这引发了我的反思"
- ✅ "笑死" / "崩溃" / "真香" / "服了" / "砍手"

### 7. 方言 / 口语 > 书面语

- ❌ "非常优秀" / "值得借鉴" / "具有重要意义"
- ✅ "很香" / "懒人" / "太太太..." / "卷到飞起" / "打工人"

### 检验标准

把自己当成一个"刚入行的同事"读这篇文章：
- 能复述出至少 3 个具体数字 / 时间 / 场景？
- 能感受到"真人写"的节奏（停顿、口语、情绪）？
- 能找出至少 1 处"如果不是亲身经历写不出来"的细节？

如果都做不到，文章 AI 味太重，需要重写。
